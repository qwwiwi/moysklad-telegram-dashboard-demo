# Партнёрские отгрузки

В учебном случае партнёр хранит свой товар и сообщает об исполненных заказах. Два собственных склада учитываются отдельно. Без отчёта партнёра о запасах его физический остаток неизвестен. Его товар не включается в стоимость запасов владельца и в расчёт покрытия спроса для собственных складов.

## Что делает прототип

Партнёр передаёт ежедневный XLSX. Одна строка описывает товар в отправке. Сумма к оплате задаётся за строку целиком, в рублях. В демо предполагается одна отгрузка артикула на заказ. Для частичных отправок в рабочем формате потребуется идентификатор отправления и строки.

Владелец проверяет распознанные строки, количество и суммы. Подтверждение увеличивает сумму к оплате партнёру. Оплата уменьшает задолженность. В ДДС выплата отражается датой фактического платежа, а статья расхода для отчёта о прибыли определяется договором. Если партнёру принадлежит товар, его стоимость и плата за исполнение могут требовать разных статей. Если партнёр хранит наш товар, понадобится отдельный учёт передачи и возврата наших запасов.

## Рабочая интеграция

1. Сервер проверяет подписанные Telegram initData, затем по Telegram ID определяет организацию партнёра и роль. Каждая операция и выборка проверяет эту привязку на сервере. Владелец видит сводный реестр, партнёр видит только свои отчёты. В прототипе роли переключаются для показа сценария.
2. Один обработчик принимает файл из Mini App или документ из личного чата бота. Исходный файл хранится в закрытом хранилище с контрольной суммой. Отчёт сохраняется черновиком.
3. Стандартный шаблон читается по колонкам. Для нестандартных файлов можно подключить модель, которая предложит соответствие колонок и артикулов. Содержимое файла считается входными данными. Модель не проводит документы и не определяет сумму долга. Неизвестные артикулы, неоднозначные даты, возвраты и расхождения тарифа попадают на проверку.
4. Сверяем строки с заказами площадки, когда подключён кабинет продавца. Ключ события включает партнёра, площадку, отправление и строку. Повтор уже принятой строки пропускаем, изменённую сумму отправляем на согласование как исправление. Отмена и возврат отражаются отдельными связанными операциями.
5. Подтверждение отчёта и запись обязательства выполняются транзакционно. Для интеграции с МоимСкладом сохраняются идентификатор первичного документа и результат отправки. Повторная отправка использует тот же идентификатор. Существующую продажу площадки нельзя повторно включать в выручку при импорте отчёта исполнителя.
6. Для закупок показываем отдельно спрос покупателей, исполнение со своих складов и исполнение партнёром. Процент заказов, отданных партнёру из-за дефицита, можно считать только при известной причине выбора исполнителя.
