# Заполнение учебного аккаунта «МоегоСклада»

Этот инструмент создаёт вымышленные данные для демонстрации Telegram Mini App. Он не предназначен для заполнения рабочего аккаунта компании.

## Сценарий

- 30 товаров для дома: термокружки, контейнеры и органайзеры.
- Два склада: существующий основной и отдельный склад с меткой A2S-DEMO.
- 180 завершённых дней: 15 мая — 10 ноября 2026 года.
- Первоначальные вложения: 10 млн ₽, из них 7 млн ₽ товаром по себестоимости и 3 млн ₽ деньгами.
- Быстрые товары продаются еженедельно, обычные — раз в две недели; 10 товаров не имеют продаж.
- Проданные количества пополняются на следующий день.
- Денежные ордера связаны с отгрузками и приёмками; взнос владельца отделён от выручки.
- Прочие расходы, включая условные учебные налоги, составляют 900 тыс. ₽ за каждые 30 дней.
- Одно перемещение показывает изменение остатков между складами без продажи.

Первый набор содержит 166 документов: 2 оприходования, 39 отгрузок, 39 приёмок, 40 приходных и 45 расходных кассовых ордеров, 1 перемещение. Всего с товарами и справочниками планируется 206 новых объектов.

Возвраты, списания и детальная модель налогов в эту версию набора не входят. Расходы укрупнены для учебного примера. Все операции без НДС, суммы вымышленные.

## Подготовка

1. Выберите отдельный учебный аккаунт. Не используйте этот инструмент в рабочем аккаунте.
2. Установите Python 3.11 или новее. Внешние пакеты не нужны.
3. Сохраните токен в закрытом файле вне репозитория:

```text
MOYSKLAD_API_TOKEN=<ваш токен; не публикуйте его>
```

4. Проверьте основную валюту учёта. Инструмент требует RUB и откажется записывать данные, если валюта отличается. Изменение основной валюты выполняется отдельно; инструмент её не меняет.

Для нашего учебного аккаунта исходная валюта была KZT. Владелец выбрал рубли; настройка выполнена через штатную форму до записи документов, когда денежные остатки были нулевыми. В существующем рабочем учёте такая смена требует отдельного анализа: числовые суммы прошлых документов автоматически не пересчитываются.

## Пробный прогон

Из корня репозитория:

```bash
python3 tools/seed_moysklad.py --env-file /путь/вне/репозитория/moysklad-key.env
```

По умолчанию выполняется только чтение и построение плана. Новых записей нет. Выводятся количества объектов по типам, а не ключи или содержимое аккаунта.

Проверить сам учебный набор без ключа:

```bash
python3 -m tools.demo_dataset
```

## Загрузка

После проверки аккаунта и плана добавьте `--apply` и путь к закрытому журналу вне репозитория:

```bash
python3 tools/seed_moysklad.py \
  --env-file /путь/вне/репозитория/moysklad-key.env \
  --receipt /путь/вне/репозитория/seed-receipt.json \
  --apply
```

Журнал содержит служебные ссылки на созданные записи, но не токен. Не публикуйте его. Прогресс сохраняется после каждого объекта.

## Повторный запуск

У записей есть префикс `A2S-DEMO` и постоянный `externalCode` в пространстве `a2s-demo-v1`. Повторный запуск с тем же набором сверяет существующие записи и использует их повторно. Если учебную запись изменили вручную, инструмент остановится, а не перезапишет её. При сравнении учитываются особенности API: время может возвращаться с миллисекундами, ссылки — с параметром раскрытия позиций, а список документов содержит меньше полей, чем полная карточка. Эти различия формата не считаются изменением учётных данных; суммы платёжных связей и идентификаторы сущностей проверяются строго.

При сетевой ошибке инструмент не повторяет POST автоматически: результат запроса мог уже сохраниться. Следующий запуск сначала читает записи и проверяет постоянные идентификаторы. Изменять seed, даты или набор и считать это тем же сценарием нельзя.

Инструмент не удаляет и не обновляет существующие записи. Он читает справочники аккаунта, поэтому сам по себе не доказывает, что выбран правильный учебный аккаунт: это нужно проверить до `--apply`.

## Финансовая сверка

Все суммы генератора — целые копейки. Для этого полного 180-дневного набора ожидаются:

| Показатель | Рубли |
| --- | ---: |
| Продажи | 27 211 520 |
| Себестоимость продаж | 17 007 200 |
| Валовая прибыль | 10 204 320 |
| Прочие расходы и условные налоги | 5 400 000 |
| Управленческая прибыль учебной модели | 4 804 320 |
| Конечный запас по себестоимости | 7 000 000 |
| Конечные деньги | 7 804 320 |
| Запас товаров без продаж | 2 320 000 |

Проверка капитала: 7 000 000 + 7 804 320 = 10 000 000 + 4 804 320. Это модель без долгов, дебиторки, дополнительных взносов и изъятий владельца.

Отдельный пример в `demo/scenario.json` относится к 30 дням и объясняет формулы. Он не является итогом этой 180-дневной загрузки.

В отчёте «Прибыльность» сверяем продажи, себестоимость и валовую прибыль; прочие расходы вычитаем отдельно. В отчёте «Деньги» сверяем денежный остаток. Движение товаров со склада не приравниваем к продажам. Отчёты остатков могут обновляться с задержкой.

## Проверки кода

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют финансовые равенства, отсутствие отрицательных остатков, повторяемость, повторный запуск без дублей, несовпадение валют, расхождение существующих записей, безопасные ошибки и пагинацию.

## Далее — приложение

После проверки источника используем эти товары и документы для мобильных экранов: сводка капитала, товары по складам, оборачиваемость, залежавшийся запас и прибыль. Интерфейс пока не реализован; эта задача подготавливает источник данных.
